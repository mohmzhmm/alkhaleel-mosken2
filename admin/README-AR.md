# لوحة إدارة مسجد الخليل

لوحة ويب ثابتة ومتجاوبة تعمل على الهاتف والكمبيوتر، وتستخدم حساب المشرف نفسه في Supabase.

## قبل النشر

1. نفّذ ملف `202609130001_unified_admin.sql` مرة واحدة في Supabase SQL Editor.
2. لا تضع مفتاح `service_role` داخل هذه الصفحة. الملف `config.js` يستخدم المفتاح العام فقط، وتحمي RLS وRPC عمليات الكتابة.
3. ارفع محتويات هذا المجلد إلى GitHub Pages أو Vercel أو أي استضافة HTTPS ثابتة.
4. سجّل الدخول بحساب موجود في جدول `mosque_admins`.

## الأقسام

- فترات الإقامة: وقت ثابت أو عدد دقائق بعد الأذان، مع عدة فترات غير متداخلة لكل صلاة.
- تعديل الأذان: وقت ثابت أو تقديم/تأخير بالدقائق خلال فترة.
- محتوى الشاشة الأفقية: الخبر العربي والسويدي وعنوان الشريط ونصه، داخل تبويب «تخصيص الشاشتين» نفسه.
- إرسال إشعار فوري إلى مستخدمي تطبيق الهاتف بالعربية والسويدية مع معاينة وتأكيد قبل الإرسال.
- إنشاء جدول مواقيت شهري بصيغة PNG أو PDF من القالب المناسب لعدد أيام الشهر، مع تمييز الجمعة تلقائيًا وكتابة اسم الشهر بلا سنة.

## قوالب الجدول الشهري

المجلد `templates` يحتوي القوالب الأربعة الأصلية بقياس `1414×2000`. لا تغيّر أبعادها أو أسماءها. يقرأ المولّد مواقيت `effective_prayer_times` حتى تشمل تعديلات الأذان التي حفظها الأدمن.

قسم الأخبار وقسم الشريط منفصلان: حفظ أحدهما لا يغيّر الآخر.

تحديثات الشاشتين تظهر خلال دقيقة، ويجلب تطبيق الهاتف البيانات عند فتحه أو عودته إلى الواجهة.
# حفظ نصوص الجدول وتخصيص الشاشتين

يتضمن هذا الإصدار زرًا مستقلًا لحفظ نصّي المربعين في قاعدة البيانات، وتبويبًا موحدًا لتخصيص الشاشتين ومحتوى الأخبار والشريط. اختر الشاشة، ثم اضغط مباشرة على العنصر داخل المعاينة؛ لن تظهر إلا أدوات ذلك العنصر. بعد ضبطه اضغط «حفظ وتطبيق». تغيير عنصر واحد لا يمس إعدادات بقية العناصر.

يظهر اسم الشهر في الورقة الشهرية بلا سنة، بينما تبقى السنة مستخدمة داخليًا لاختيار الأيام والمواقيت الصحيحة.

يمكن اختيار حجم خط الأيام وأسماء الأيام وأوقات الصلاة من منزلق «حجم خط الجدول» قبل إنشاء المعاينة أو تنزيل PNG/PDF.

عند فتح معاينة تخصيص الشاشة يظهر شريط أصفر داخل الشاشة. مرّر المؤشر فوق العنصر ثم اضغط عليه؛ سيُحاط العنصر باللون الأصفر وتظهر أدواته وحده فوق المعاينة.

يجب تنفيذ ملف `202609220001_screen_customization.sql` الموجود في جذر المشروع عبر Supabase SQL Editor مرة واحدة قبل استعمال الحفظ والتخصيص. إذا نفذته مع التحديث السابق فلا تُعد تنفيذه.
